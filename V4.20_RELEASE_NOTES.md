# EZTV v4.20 — DVR Lock-In + Real USB Downloads

This version is intentionally narrow. The smooth ordinary Live TV path from v4.19 is protected.

## DVR Live
- Removed the v4.19 fake 1 GB / 3.5 GB future `Content-Length` and `Accept-Ranges` response from the still-growing DVR stream.
- Restored the proven unknown-length localhost MPEG-TS tail so Media3 can lock onto the picture immediately instead of trying to reason about unwritten future bytes.
- DVR writer, packet alignment, USB storage, and permanent recording code are left intact.
- 30-second rewind/forward is now controlled by EZTV itself: it reconnects the localhost player at an already-written, 188-byte-aligned file offset.
- The DVR timeline is estimated from the bytes actually written and the current play offset rather than Media3 pretending the growing file has a fixed duration.
- Fire remote FF/RW uses the same app-controlled DVR jump.

## Downloads
- New IPTV downloads no longer use Android `DownloadManager`.
- Added one lightweight EZTV foreground download service using OkHttp and direct streaming file I/O.
- Writes straight to the verified EZTV USB/app storage directory as `filename.ext.part`, then renames only after a complete transfer.
- Uses one 128 KB memory buffer; the whole movie/episode is never held in RAM.
- Reuses EZTV's provider User-Agent first and retries once with the browser-compatible VOD User-Agent on HTTP 403/406.
- Honors Provider Streams 1/2/3 budgeting and still allows only one background VOD download at a time.
- Shows real byte/percentage progress and an actual failure reason instead of sitting forever on “Starting download…”.
- One-time migration preserves completed old DownloadManager files but clears/cancels stuck v4.19 system jobs so they cannot block the first v4.20 download.
