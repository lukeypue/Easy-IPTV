# Zako 4.32 Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the last-mile Zako polish pass without destabilizing playback: lower VOD catalog peak memory, smooth startup/channel changes, unify text-entry layout, modernize the blue/lime/pink UI, and improve mini-guide readability.

**Architecture:** Keep the existing single-player, single-coder architecture intact. Make bounded changes through the existing release patch chain so every release remains reproducible. Replace Xtream VOD whole-response String/JSONArray parsing with streaming JsonReader parsing, defer nonessential startup housekeeping, precompute Live queues instead of rebuilding them per tune, and preserve the existing playback engine/risk controls.

**Tech Stack:** Android/Kotlin, Jetpack Compose, Media3/ExoPlayer, OkHttp, android.util.JsonReader, Python release patch/verifier scripts, GitHub Actions.

**Spec:** User-approved in-chat design on 2026-09-10.

## Global Constraints

- Fire TV remote/D-pad remains first-class.
- Android phone uses the same Zako/Amazon-style keyboard layout as Fire TV.
- Keep hot-pink focus indication.
- Keep the newer deep/electric blue visual foundation.
- Category surfaces become more rounded/bubble-like with lime-green accents.
- Mini-guide remains compact and shows exactly three primary browse rows.
- Remove the mini-guide helper line “Browse / OK tunes / 3 rows stay on screen”.
- Make the three mini-guide rows and text larger for older viewers.
- Mini-guide program titles use the same bright yellow as the main guide.
- Do not add heavy blur, shader, animation, or background polling on ~1 GB Fire TV hardware.
- Do not change the proven playback/recording engine unless a measured optimization is isolated and low-risk.
- Only ChatGPT modifies code; outside AIs are reviewers only.
