# EZTV v4.18 — engineering handoff to next AI

## Read first
This is a Fire TV IPTV CLIENT, not a streaming service. Keep these constraints:
- One provider connection at a time.
- Single-bitrate IPTV input; do not invent ABR/CDN/backend fixes.
- Fire Stick class hardware; steady CPU/GC/disk work must stay tiny.
- Smooth Live must remain available as the lightest, most reliable live path.
- DVR/recording/downloads are a core differentiator, but cannot be allowed to destroy live smoothness.

## User's v4.17 on-device findings
- Simple Mode made live TV dramatically smoother.
- Normal DVR Live had repeated buffering on a channel that was smooth in TiviMate.
- A weak channel improved but sometimes stopped until Play was pressed.
- OK showed a one-channel popup instead of a true mini guide.
- Voice button failed because no speech-recognition app was installed.
- Recording showed 0 MB.
- On-demand disappeared after the live-first/lazy-loading change.
- USB 128 GB drive was connected but saved media appeared to use internal storage.
- User wants captions, visible buffer status, better focus, posters/logos, configurable retention, and recordings/downloads as the major product advantage.

## v4.18 changes to preserve
1. Smooth Live defaults ON for new installs; explicit existing user setting is preserved.
2. OK on live always opens EZTV's bottom mini guide; Media3's stock controller no longer gets first shot.
3. Mini guide shows recent/nearby channels, logos, current/next program, buffer seconds/bar, actual playback path, CC, AFR and source FPS→display Hz.
4. Mini guide can switch Smooth Live/DVR Live and AFR without hiding the real state from the tester.
5. On-demand lazy-load race fixed; VOD catalog loads only when Movies/Series/Search is entered.
6. CEA-608/text-track caption selection added.
7. Voice button is hidden when no recognizer Intent handler exists.
8. Root focus begins top-left/first menu item; exit dialog focuses Stay with TV focus styling.
9. USB is considered usable only after an actual write probe. App-specific removable path first; legacy Fire OS 7 portable path only with normal storage permission.
10. DVR scratch uses verified USB if selected. Internal DVR cap ~1 GB; USB cap ~3.5 GB, then live falls back direct rather than freezing.
11. Recording eligibility checks the real DVR writer state. 0-byte failures are removed.
12. Downloads use DownloadManager status: partial files are not marked complete.
13. Downloads, live/VOD playback and recordings obey the same one-provider-connection rule. One provider download at a time.
14. EPG memory window reduced to ~48 hours rather than retaining a week.
15. Hardware/native audio first, FFmpeg fallback; Media3 1.9.0 paired with matching Jellyfin FFmpeg 1.9.0+1.
16. Clean MPEG-TS packet publishing from v4.16 remains intact.

## Important product/storage research
Amazon's current Fire TV Appstore test criteria warn against continuously buffering video/audio into eMMC because it can exceed the Fire TV eMMC foreground-write guideline. Do not casually revert Smooth Live to an internal-disk DVR default. A verified removable drive is the preferred place for DVR Live.

Portable USB behavior varies by Fire OS. Never claim “USB supported” from mount detection alone. Keep the actual create/write/delete probe and visible fallback messaging.

## Highest-value next evidence

- Smooth Live + AFR OFF

- same mode + AFR ON
