# EZTV v4.17 — GPT-5.6 Sol release notes

This build is intentionally focused on Fire TV smoothness, remote usability, and player compatibility. It does not copy TiviMate code; TiviMate and IPTV-user feedback were used only as product/behavior references.

## Build compatibility
- Android compile SDK raised to 35 because the newer Media3 generation requires it; app target SDK remains 34.
- Android Gradle Plugin raised to 8.6.1 while GitHub Actions stays on Gradle 8.7 / Java 17.
- The project zip still intentionally uses the existing GitHub Actions build path; no local Gradle wrapper launcher was added.

## Live TV / Fire Stick performance
- Live playlist data refreshes first. Large Movies/Series catalogs no longer refresh behind live TV on a timer.
- Full XMLTV parsing no longer runs behind full-screen playback, and Simple Mode skips the bulk XMLTV job entirely.
- The live governor backs off to a 6-second check when the buffer is healthy and returns to 2-second checks only when the cushion is thin/buffering.
- The v4.16 complete-188-byte MPEG-TS publishing fix and stale-retry generation guard are retained.
- Media3's direct HTTP path now uses EZTV's provider User-Agent, permits legitimate HTTP/HTTPS redirects, uses a 15-second connect timeout and a 20-second read timeout instead of Media3's short default read timeout.

## Simple Mode
- Simple Mode now changes LIVE TV only.
- Live DVR/timeshift, recording, pause/rewind and the speed governor are disabled.
- It keeps the normal user-selected lock-in cushion instead of forcing an aggressive 1.5-second start.
- Movies, Series, Search, Downloads and already-saved recordings remain available.
- Movies/Series data loads only if the viewer opens an on-demand/search screen.
- Existing one-connection recording protections remain in place.

## Recent-channel mini guide
- Press OK during live TV to show a lightweight recent-channel strip over the picture.
- Stores up to 7 distinct channel identities, not category indexes.
- Shows channel logos and current show text when EPG information is already available.
- D-pad focus and OK are routed to the guide while it is open instead of being swallowed by the full-screen player handler.
- First-card focus is delayed one frame-sized beat so Fire TV has time to attach the LazyRow item.
- Recent channel identities persist across app restarts when the same playlist still contains them.
- Auto-hides after inactivity; no per-frame or permanent mini-guide task is added.

## Search / visual polish
- Live results keep channel-logo treatment.
- Movie and series search results use portrait poster cards rather than treating everything like a channel row.

## Downloads
- Removed the forced 14-day retention policy.
- User can choose: keep until deleted, or a finite retention period.
- Existing v4.16-and-earlier downloads are migrated to "keep until deleted" once on upgrade so nothing gets unexpectedly removed.
- Changing retention updates the existing download library as well as future downloads.

## VOD / episode compatibility
- Media3 upgraded from 1.3.1 to 1.9.0.
- Matching Jellyfin FFmpeg audio extension upgraded to 1.9.0+1.
- FFmpeg remains available as fallback, while native/hardware audio is tried first to reduce Fire Stick CPU use.
- On-demand media uses a more tolerant MPEG-TS extractor path (`FLAG_DETECT_ACCESS_UNITS` + `FLAG_ALLOW_NON_IDR_KEYFRAMES`) without adding that parsing cost to normal live TV.
- The player HTTP source now uses the same EZTV User-Agent and accepts provider HTTP↔HTTPS redirects.

## Automatic frame-rate matching (AFR)
- Separate settings for Live TV and Movies/Series.
- Video FPS is read after playback reaches READY, with a short delayed retry window so the track format has time to populate.
- EZTV selects only display modes at the same physical resolution and only refresh rates that are clean integer multiples of source FPS.
- Preferred display mode is reset when AFR is disabled/leaving playback.

## Not changed on purpose
- The core disk-backed live DVR architecture remains intact.
- There is still one global ExoPlayer shared by the full-screen and mini-player views.
- This release does not attempt a risky PlayerView/surface architecture rewrite.
- No extra analytics, per-packet scanner, per-write diagnostics, server/backend, or extra provider connection was added.
