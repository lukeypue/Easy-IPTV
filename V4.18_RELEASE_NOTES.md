# EZTV v4.18 — GPT-5.6 Sol release notes

## Goal
Make the Fire TV app lighter and more predictable than v4.17 while strengthening the features that can differentiate EZTV: Smooth Live, DVR/recording, offline downloads, a real remote-native mini guide, visible buffer/AFR state, and removable-storage support where Fire OS actually permits it.

No TiviMate proprietary code is included or copied. TiviMate/Xfinity behavior was used only as a UX reference.

## Live TV
- **Smooth Live is the default for new installs.** It uses the direct provider path with no live DVR writer/server, no live recording, no pause/rewind, and no DVR governor.
- **DVR Live** remains available for pause, rewind and recording. A verified USB drive is strongly recommended.
- Fixed the hidden direct-rescue state so manual channel changes / retries do not make Simple Mode appear stuck on after the setting is changed.
- Added event-driven reconnect for live streams that end cleanly instead of throwing a player error, addressing channels that unexpectedly stop and wait for Play.
- Time-based Media3 LoadControl remains in place (`C.LENGTH_UNSET`, time thresholds prioritized).
- DVR cushion speed assist is optional; normal playback stays exactly 1.0x after lock-in unless the user explicitly enables assist.

## Mini guide
- Live **OK always opens EZTV's mini guide** instead of Media3's generic first popup.
- Mini guide is pinned to the bottom like a cable-box surf bar.
- Shows current channel logo, current/next program, recent/nearby channels and logos.
- Includes a live buffer bar plus actual seconds buffered.
- Shows actual path: SMOOTH LIVE / DVR LIVE / DIRECT RESCUE.
- Shows source FPS → active display Hz and AFR ON/OFF so the customer can verify AFR actually changed.
- Provides one-press CC, AFR, live-mode, retry, and Settings controls.
- Status polling exists only while the mini guide is visible; no permanent UI tick was added.

## On-demand / player
- Fixed lazy Movies/Series catalog loading race that could leave on-demand empty after live-only startup.
- Added visible on-demand loading state.
- Retains tolerant MPEG-TS extraction for problematic VOD/episodes while keeping the cheaper extractor path for live TV.
- Media3 1.9.0 + matching Jellyfin FFmpeg 1.9.0+1 remain paired.
- Hardware/native audio gets first chance; FFmpeg remains available as fallback.

## Search / artwork / voice
- Live search results use channel logos.
- Movies and Series use portrait poster art.
- Voice-search button is hidden when Fire OS has no installed speech-recognition activity, avoiding the misleading “needs an app” failure.

## Closed captions
- Adds Settings CC on/off.
- Adds a mini-guide CC toggle and Menu-button shortcut.
- Enables Media3 text tracks and supplies CEA-608 channel-1 format hints for TS streams that carry captions without clean PMT declaration.
- Captions still require the provider/content to contain a usable subtitle/caption track.

## Focus / remote polish
- Root menu requests focus on its first/top item.
- Exit dialog initially focuses **Stay**.
- Exit buttons use the same TV focus treatment/hot-pink outline as the rest of the app.

## External USB storage
- Keeps the external-drive feature, but never claims it works until a real create/write/delete probe passes.
- First tries Android app-specific removable volumes returned by `getExternalFilesDirs()`.
- On Android-9-class Fire OS, can also use a mounted removable `/storage/<volume>` path after the normal legacy storage permission is granted.
- Settings has contextual **Allow USB** and **Recheck USB** actions rather than an unconditional startup storage prompt.
- New downloads/recordings write directly to the selected destination. Nothing is silently “moved to USB later.”
- Temporary DVR uses the verified USB when selected; otherwise Smooth Live is recommended.

## Recording reliability
- Recording eligibility now checks the *real* DVR writer state, not only a `liveMode` flag.
- If direct-rescue playback was active, recording retunes the current channel back through DVR before teeing.
- Recordings screen refreshes size only while a recording is active and can show KB before the first whole MB.
- Zero-byte failed recording placeholders are deleted.
- Channel/VOD changes are blocked while a watched-channel recording owns the single provider connection.
- Scheduled recording stops live playback first if it needs the provider connection.
- Scheduled/manual recording cancels an in-progress provider VOD download before starting, so two provider sockets are never deliberately created.

## Download reliability
- Download state now uses Android DownloadManager STATUS values; a partially written file is no longer treated as a finished download just because bytes exist.
- Only one provider download is allowed at a time.
- Starting a download stops provider playback first so the IPTV account's single connection belongs to the download.
- Remote Live/VOD playback is blocked while a provider download is active; local saved files remain available.
- Finished downloads remain under the user-selected retention policy: forever / 7 / 14 / 30 / 60 / 90 days.
- USB destination is attempted directly. If that specific Fire OS DownloadManager rejects it, EZTV reports the fallback instead of falsely claiming USB storage.

## Memory / Fire Stick work
- Xtream Live loads first; Movie/Series catalog is lazy.
- XMLTV is not parsed behind full-screen playback and EPG memory is limited to a much smaller useful future window.
- No PCR-per-packet scanner, per-write throughput diagnostics, large image animations, or permanent mini-guide status polling were added.

## Storage / Appstore note
Amazon's current Fire TV test criteria explicitly caution developers not to continuously buffer video/audio to eMMC because that can exceed its foreground write guideline. This is a major reason v4.18 defaults new users to Smooth Live and treats a verified removable drive as the preferred home for DVR Live.

## Build status
The source tree does not contain `gradlew` or the Gradle wrapper JAR and this environment has no Android SDK, so a real Android APK cannot be compiled locally here. The included GitHub Actions workflow builds with Java 17, Gradle 8.7, AGP 8.6.1, compileSdk 35, and uploads `EZTV-v4.18-debug`.
